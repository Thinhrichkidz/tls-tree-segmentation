## Executive summary

**Verdict: the numbers are sound but the report is not ready to submit.** Almost every number in the abstract, results, Table 4, Table 5 and Fig. 2 matches my independent recomputation from the raw outputs (point-cloud headers, `tree_attributes.csv`, per-tree JSON). The report is careful about what it does not claim: no field validation, no accuracy, no biomass. The problems are elsewhere: it is unfinished, the status rules it describes are incomplete, one interpretation in the Discussion is wrong, and the repository does not contain the code behind the results.

Findings: **3 CRITICAL, 8 MAJOR, 9 MINOR, 4 OBSERVATION** (24 total). Claim register: 93 claims, of which 63 VERIFIED, 14 PARTLY_SUPPORTED, 7 UNVERIFIABLE, 6 UNSUPPORTED and 3 CONTRADICTED.

Top 5 issues:
1. **F-001** There are 19 `[To be completed]` placeholders, 2 `[VERIFY]` tags and an empty Fig. 3, including the student ID, the AI declaration and the re-fit results.
2. **F-002** The AI-use declaration is still a bracketed draft, and it under-states what the AI agents did: they wrote the QC/status rules and the whole measurement pipeline, and they compiled the reported statistics.
3. **F-003** The repository (50% of the mark) has 7 commits made on 20–21 Oct. It contains none of the measurement pipeline that produced the results and no v4 source. The report's "released" files are not in it.
4. **F-005** Table 3 does not state the rules that were actually applied. Applying Table 3 as written gives 69 VALID heights and 66 VALID DBHs, not the reported 53 and 43.
5. **F-004** The Discussion reads "25 labelled UNCHANGED" as "unchanged from the automated output". The label actually means "no specific current flag".

Two facts in the brief were wrong:
- The TreeData file is for **WSF_ML2A**, and it covers 37 sites. The report never presents it as validation data.
- The "67 of 163" figure is correct, but only for the round-2 set (`manual_seg_v2`). It is not correct for the clouds that were measured.
